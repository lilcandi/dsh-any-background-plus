dsh-any-background 安装说明
===========================

版本：0.4.4
适用：DSH 0.1.5-rc.2 ~ 0.2.0-rc.1
来源：fork 自 Tkingxiao/dsh-any-background（MIT），v0.4.0 起的改动为本 fork 所作


一、这个插件是什么
------------------

给 DSH 换背景的插件：图片 / 渐变网格 / 着色器 / 图案四种背景。

页面右下角有一个圆形按钮，按一下立刻切换壁纸；定时轮换模式下按钮
外围会有一圈倒计时，提示还有多久自动切换。按住可以把它拖到任意
位置（位置会被记住），右键一下送回角落。
（v0.4.3 修复：此前按钮会显示成左上角的方块，且点击无效。
  v0.4.4 起按钮改用宿主原生浮动按钮的样式，并可拖动。）

v0.4.2 起有「左右双图轮播」：同一轮播每次前进两张图，左边一张、
右边一张，以窗口绝对中心为分界，左右各占一半。这样既能看到壁纸，
主体又不会被中间的会话栏挡住。

轮播来源有三种：轮换池（手动添加的图片）、单个图片文件夹、以及
左右各一个文件夹（v0.4.2 新增）。


二、安装
--------

解压这个 zip，得到一个文件夹，里面有 9 个文件。然后在解压出来的
目录里执行（把 <解压目录> 换成实际路径）：

    node --expose-internals "%APPDATA%\npm\node_modules\@deepseek-ai\dsh\lib\bin.js" ^
      plugin --profile web add "file:<解压目录>" ^
      --store-dir "<解压目录>\.pnpm-store" --reporter=append-only

如果 pnpm 报
    ERR_PNPM_LOCKFILE_WRITE_FILE ... os error 5
就改用 npm：

    npm install --cache .\.npm-cache --no-audit --no-fund ^
      --no-package-lock --legacy-peer-deps

装完后重启 DSH（Node 那一半是启动时读进内存的，不重启不生效），
打开设置 → 外观 → 背景，就能看到插件面板。


三、升级
--------

覆盖解压目录里的 9 个文件（保持文件名不变），然后重启 DSH。
纯浏览器半的改动只需刷新页面；动了 Node 半的改动必须重启。


四、卸下
--------

    node --expose-internals "%APPDATA%\npm\node_modules\@deepseek-ai\dsh\lib\bin.js" ^
      plugin --profile web remove dsh-any-background

卸载不会删除你的配置和数据，它们留在：

    C:\Users\<你>\.dsh\.dsh-any-background-data\


五、这个版本做了什么（v0.4.4）
------------------------------

1. 右下角按钮可以拖动，位置会被记住
   按住拖到任意位置即可。拖动用的是指针捕获，超过 4 像素才算拖动，
   否则仍按点击处理；松手时把坐标写进浏览器的 localStorage（键名
   dab-orb-pos），而不是写进插件配置——位置属于「这个窗口在这块
   屏幕上」，不属于主题；写进配置还会把 Node 半部拖进一个纯显示的
   事情里，改一次要重启宿主才生效。
   默认仍在右下角：只有存过位置才会按存的走。右键一下即清除记录、
   回到角落（而不是回到一个「接近角落」的坐标）。
   存下来的位置在每次窗口尺寸变化后都会重新夹回视口内（尺寸取自
   按钮自身的记录值），否则在宽屏上存下的位置到窄屏就会跑到屏幕外。

2. 按钮改成宿主自己的浮动按钮样式，不再是自己描的近似款
   样式抄自宿主 ChatView.module.css 里那个「回到底部」浮动按钮
   （类名 EvIC1a_toBottom）：填充用 --dsw-alias-button-floating-fill
   （悬停用 -hover），阴影用 --dsw-elevation-panel，发丝描边由
   --dsw-elevation-stroke-color: var(--dsw-alias-border-l3) 提供，
   图标色用 --dsw-alias-label-primary，圆角 border-radius: 100px 配
   corner-shape: round，尺寸 34px 见方。
   也就是说按钮的配色、明暗切换、阴影都直接跟随设计令牌，不再逐条写死；
   实测（活页面）：border-radius 100px、corner-shape superellipse(1)、
   cursor grab、图标色与 --dsw-alias-label-primary 完全一致。

3. 顺带修掉一个入场动画留下的隐患
   入场动画原先用 animation-fill-mode: both，动画结束后仍会一直
   顶着最后一帧的 transform: none，导致 hover / 按下时的缩放永远
   不生效。改成 backwards——这才是入场动画该用的：开始前保持首帧，
   结束后完全交还属性。

4. 减弱动效的设置原先够不到这个按钮
   那段样式限定在 .dab-root 里，而按钮被 portal 到 <body>，已经不在
   那棵子树里，于是唯一一个「每次轮播都动、每秒重绘一次」的元素反而
   不受这个偏好约束。现在那条规则里单独列出了它的选择器。

5. Portal 改挂 <body>：这是真缺陷，不是洁癖
   所有 --dsw-alias-* 令牌只声明在 body / body[data-ds-dark-theme]
   上（实测 209 处声明、没有 :root、没有 html）。而 portal 宿主原先
   挂在 document.documentElement —— 它是 <body> 的兄弟节点、不是祖先
   ——于是取不到任何令牌：提示条（toast）的
   background: var(--dsw-alias-bg-layer-3, ...) 整个解析为空，提示条
   全透明、边框变黑，只有 z-index 生效。
   用真的 .dab-toast 类在仿造的 portal 宿主里各挂一次实测：挂 <body>
   算出 background: rgba(92, 95, 69, 0.5)、border 1px solid
   rgba(117, 119, 95, 0.22)；挂 <html> 算出 background: rgba(0, 0, 0, 0)、
   两个令牌查询都是空。按钮当初也是这么挂的，同样取不到令牌——它在
   v0.4.3 看起来正常，只是因为那次把默认样式写成了固定值。

6. 提示语把操作方式写进去
   悬停提示现在是「立即切换壁纸 · 还剩 1:21 · 拖动可移动，右键归位」，
   在原有的倒计时后面追加了拖动/右键那一句，中英双语同步。


六、v0.4.3 做了什么
-----------------

1. 修复：右下角按钮显示成左上角的方块
   按钮的全部外观住在设计系统样式表里，而那份样式表原先只在打开设置
   对话框时才注入。按钮却在插件启动时就进了 DOM，于是没有
   position:fixed，退化成浏览器默认方块。现在挂载按钮时先注入样式。

2. 修复：点击右下角按钮没有反应
   点击时去 store 的动作对象里取 rotateNow，但那份对象里只有三个
   同步动作，rotateNow 是给设置页的另一份对象。取到 undefined 后
   守卫静默返回，于是「函数不存在」看起来和「按钮坏了」一模一样。
   现在把 rotateOnceNow 直接作为必填参数传入，并加 .catch 上报失败。

   设置页的「立即切换」按钮一直是好的——正是这一点证明轮换逻辑本身
   没问题，把故障锁定在浮动按钮的动作来源上。


七、v0.4.2 做了什么
-----------------

1. 视频功能按代码彻底删除
   所有视频端点、路由、上传处理器、mime 表、文件名白名单、文件夹
   扫描、逐元素播放层及其设置全部删除，不是隐藏。
   BackgroundType 不再含 'video'；轮播不再含 media / videoFolder /
   videoName / videoVolume / videoAlign / ended；整个
   src/client/utils/video.ts 模块已删除。
   旧配置里若还写着视频轮播，归一化时会回落到图片。

2. 新增左右双图轮播
   轮播面板新增「左右双图」开关，同一轮播的两张不同图片同时铺在
   视口左右两侧，避开中间会话栏。

3. 是同一个轮播推进两次，不是第二个轮播
   左道用既有的 pickRotationIndex()；右道用 nextLaneIndex()，从左道
   往前走一步。走一步而不是再抽一次是刻意的：洗牌的随机数没有播种，
   两次独立抽取偶尔会撞在一起、把同一张图画两遍。order 模式下这一对
   就是相邻的两张。选中的结果以 laneItems 持久化。

4. 分界是窗口的绝对中心，两条车道在构造上等宽
   wpLeftEl 与 wpRightEl 是一对对等的半视口元素，各自贴住一侧，
   拿到完全相同的像素宽度 Math.floor(innerWidth * 0.5)，所以视口
   宽度是奇数时也不会有一条车道宽出一个像素。
   让图片够到接缝的那点外扩只在 center 模式下施加：fit 下图片本来
   就装在车道内，此时再外扩会让两条车道在接缝处重叠，谁后画谁赢
   那一条——视觉上就是一张图压着另一张。

5. 两张图的原始尺寸分别测量
   车道几何需要两张图各自的真实尺寸都在布局前拿到。尺寸由一张按
   URL 索引的小表保存并提供同步查询；用单槽缓存会让后运行的车道
   占据测量，把先运行的那条推进按比例兜底，于是一张图按自己的盒子
   铺开、另一张按比例缩小——正是「一张比另一张大」。

6. 边缘淡化对两条车道一视同仁
   滑块按每张图自身的比例读取，坡道用同样的 px 停靠配方、对着同样
   的盒子计算，并且恒定施加（不会因为某条车道比自己的盒子宽就跳过）。

7. 两条车道是两个独立磁盘槽位
   右上角那张有自己的文件 wallpaper-right.jpg 与专属路由
   /dsh-any-background/wallpaper-right。候选池只有一张图、或 dual
   关掉时，服务端不回报右侧 URL，浏览器半据此撤掉第二个面板。

8. 设置页预览也是双图
   主题面板的预览大图按同样的 50/50 栅格绘制，看到的就是墙面实际的
   样子。

9. 新增第三种来源：左右各一个文件夹
   左边可以设一个文件夹、右边可以设另一个文件夹，各自就地读取，
   左右两条车道各走自己的目录。
   频率与模式仍是共用的——要的是两个来源，不是两次轮播。
   两个文件夹都选好之后才换壁纸：只选了一个时不预览，避免半面墙。
   左右各留一个游标：右道的位置按它正在显示的文件名在自己的目录里
   反查，所以左道往前走不会把右道在另一个列表里的位置带跑；两个目录
   张数不同也能各自正确回绕。
   单选文件夹模式继续可用，双文件夹只是第三种来源。


八、怎么用左右双图
------------------

设置 → 外观 → 背景 → 轮播：

  1. 先选一个来源：轮换池（手动添加的图片）或图片文件夹。
  2. 点「左右双图」开关打开。
  3. 若来源是轮换池，需要池里至少有 2 张图，打开开关时会立刻落一条
     右车道；若只有 1 张，服务端不回报右侧 URL，右面板不会出现。

打开开关后墙面上会出现两条车道，各自轮换；每次前进左右一起换，
一对两张不同的图。

想只留一张整幅图，把「左右双图」关掉即可，「边缘淡化」滑块对单图
和双图都有效。


九、怎么用两个文件夹（v0.4.2 新增）
-----------------------------------

设置 → 外观 → 背景 → 轮播 → 来源选「图片文件夹」：

  1. 点「选择文件夹」选左边那个目录。
  2. 点「选右文件夹」选右边那个目录。
  3. 两个都选好之后壁纸立刻换成一对，之后按共用的频率与模式一起前进。

面板上会出现两行路径，分别是左、右文件夹与各自的图片张数。
想换掉其中一个，点对应的按钮重选即可；重选左文件夹不会丢掉右文件夹。
想回到单选文件夹，点清除即可（左右两个目录会一起忘掉）。

注意：只有选了左文件夹之后才能选右文件夹——右文件夹是给左文件夹
「配对」的，单独存在没有意义。


十、已知事项
------------

- 轮播频率支持：每次刷新 / 每 N 分钟（1–1440）/ 每天 / 每周。
- 边缘淡化滑块范围 0–60（百分比）。
- 图片文件夹最多读取 20000 张，按文件名排序。
- 支持的图片格式：jpg / jpeg / png / gif / webp。
- 右下角按钮只在「每 N 分钟」模式下显示倒计时圆环；其他模式按钮
  仍然可用，只是没有倒计时可数。
- 右下角按钮的位置记在浏览器本地（localStorage），不写进插件配置；
  换浏览器或清掉站点数据后回到默认的右下角。
- 若插件行显示为禁用，通常是 DSH 版本超出上面「适用」范围，
  升级 DSH 或改装对应版本的插件包即可。
- 单图模式下「透明度」「模糊」滑块只作用于右侧图层，左侧车道不跟随
  （双图模式的已知缺口，尚未修）。
